== Общее описание

=== Назначение
Telegram-бот для автоматического мониторинга новостей о фигурках с форума https://bbs.bbicn.com/ и Facebook страницы https://www.facebook.com/hottoys с отправкой уведомлений всем подписчикам о новых постах и темах.

=== Цель проекта
Создать Telegram-бота, который будет регулярно парсить целевые источники, извлекать информацию о новых темах и постах, и автоматически рассылать уведомления всем подписанным пользователям в реальном времени.

=== Основные возможности
* Парсинг форума BBS BBICN и Facebook Hot Toys для извлечения новых тем и постов
* Автоматическая рассылка уведомлений всем подписчикам
* Управление подписками пользователей (подписка/отписка)
* Фильтрация контента по категориям и ключевым словам
* Административная панель для управления ботом
* Отложенная отправка сообщений для избежания спама

== Функциональные требования

=== Основные функции

==== Парсинг источников
* *Мониторинг разделов*: Отслеживание изменений в указанных разделах форума и социальных сетей
* *Извлечение тем*: Получение заголовков, авторов, дат создания новых тем и постов
* *Извлечение контента*: Получение содержимого постов, включая текст и изображения
* *Метаданные*: Сбор дополнительной информации (количество просмотров, ответов, лайков)
* *Дубликаты*: Исключение повторных уведомлений

==== Telegram Bot функции
* *Подписка/отписка*: Управление списком подписчиков
* *Массовая рассылка*: Отправка уведомлений всем активным подписчикам
* *Категории*: Подписка на конкретные категории (Hot Toys, ThreeZero, Sideshow)
* *Настройки*: Персональные настройки уведомлений
* *Модерация*: Административные команды

==== Пользовательские команды
* `/start` - регистрация и приветствие
* `/subscribe` - подписка на уведомления
* `/unsubscribe` - отписка от уведомлений
* `/categories` - управление подписками по категориям
* `/settings` - персональные настройки
* `/help` - справка по командам
* `/status` - статус подписки

==== Административные команды
* `/admin_stats` - статистика бота
* `/admin_broadcast` - ручная рассылка
* `/admin_users` - управление пользователями
* `/admin_sources` - управление источниками
* `/admin_logs` - просмотр логов

=== Целевые источники
* **BBS BBICN Forum** - https://bbs.bbicn.com/
  - Главная страница форума
  - Раздел "Hot Toys"
  - Раздел "ThreeZero"
  - Раздел "Sideshow"

== Технические требования

=== Технологический стек

==== Backend (Go)
* *Язык*: Go 1.21+
* *Web Framework*: Echo v4 (для webhook и admin panel)
* *Telegram Bot API*: github.com/go-telegram-bot-api/telegram-bot-api/v5
* *HTTP Client*: Standard net/http + context
* *HTML Parser*: github.com/PuerkitoBio/goquery
* *Social Media*: Facebook Graph API client
* *Database*: PostgreSQL 15+
* *ORM/Query Builder*: sqlc для type-safe SQL
* *Migrations*: golang-migrate
* *Cache*: Redis 7+
* *Queue*: Redis для очереди сообщений
* *Configuration*: github.com/spf13/viper
* *Logging*: github.com/rs/zerolog
* *Monitoring*: Prometheus + Grafana

==== Инфраструктура
* *Контейнеризация*: Docker + Docker Compose
* *Reverse Proxy*: Nginx (для webhook)
* *Environment*: Docker containers
* *CI/CD*: GitHub Actions
* *SSL*: Let's Encrypt для webhook

!theme plain
skinparam backgroundColor #FFFFFF

title Последовательность обработки новых постов и уведомлений

participant "Scheduler" as Scheduler
participant "Scraper" as Scraper

participant "Facebook" as Facebook
participant "Database" as DB
participant "Notification Service" as NotifyService

participant "Redis Queue" as RedisQueue
participant "Message Formatter" as Formatter
participant "Telegram API" as TelegramAPI
participant "Subscribers" as Users

== Background Scraping ==
note over Scheduler: Runs every 5 minutes
Scheduler -> Scraper: Start scraping cycle

== Parse BBS Forum ==
Scraper -> BBSForum: GET forum pages
BBSForum -> Scraper: HTML content
Scraper -> Scraper: Parse new topics/posts

== Parse Facebook ==
Scraper -> Facebook: Graph API request
Facebook -> Scraper: JSON posts data
Scraper -> Scraper: Parse new posts

== Check for New Content ==
Scraper -> DB: Check for duplicates by hash
alt New content found
    Scraper -> DB: INSERT new topics/posts
    DB -> Scraper: New post IDs
    
    == Prepare Notifications ==
    Scraper -> NotifyService: Send notification request
    NotifyService -> DB: Get active subscribers
    DB -> NotifyService: Subscriber list
    
    loop For each new post
        NotifyService -> Formatter: Format message
        Formatter -> NotifyService: Formatted message
        
        loop For each subscriber
            NotifyService -> Queue: Add message to queue
            Queue -> RedisQueue: Enqueue message
        end
    end
end

== Message Processing ==
note over Queue: Background worker processes queue
Queue -> RedisQueue: Dequeue message
RedisQueue -> Queue: Message data
Queue -> TelegramAPI: Send message
TelegramAPI -> Users: Deliver notification

alt Rate limit exceeded
    TelegramAPI -> Queue: Rate limit error
    Queue -> RedisQueue: Re-queue with delay
else Success
    TelegramAPI -> Queue: Message sent
    Queue -> DB: Update notification status
end

== Безопасность

=== Меры безопасности

==== Telegram Security
* Проверка секретного токена webhook
* Валидация Telegram User ID
* Защита от спама и флуда
* Blacklist для заблокированных пользователей

==== Rate Limiting
* 5 команд в минуту на пользователя
* 30 сообщений в секунду от бота
* Защита webhook от DDoS

==== Data Protection
* Хеширование чувствительных данных
* Логирование без персональных данных
* GDPR-совместимое хранение данных

==== Admin Security
* JWT токены для admin panel
* Двухфакторная аутентификация для админов
* Аудит лог административных действий

== Производительность

=== Оптимизации

==== Telegram API
* Batch отправка сообщений
* Rate limiting для избежания блокировок
* Retry механизм с экспоненциальной задержкой

==== Очередь сообщений
* Redis-based message queue
* Background workers для обработки
* Приоритизация сообщений

==== База данных
* Индексы на часто запрашиваемые поля
* Партиционирование таблицы notifications
* Connection pooling (max 10 соединений)

==== Кэширование
* Redis кэш для пользовательских данных
* In-memory кэш для конфигурации
* Кэширование результатов парсинга
